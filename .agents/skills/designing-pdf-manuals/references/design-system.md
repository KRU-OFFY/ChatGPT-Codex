# Design System Reference

## Default Visual Direction

Use the brief's visual identity when supplied. Otherwise a strong default for technical manuals is:
- deep navy for structure and headers,
- orange for emphasis and numbered steps,
- white / warm light gray for page fields,
- restrained green for PASS/safe states,
- restrained red for warnings/fail states.

The default is a starting system, not a mandatory brand.

## Page Baseline

- Default format: A4 portrait.
- Keep consistent safe margins on all pages.
- Reserve stable header and footer zones.
- Keep page number placement consistent.
- Use a grid so images, callouts, tables, and text align predictably.

## Typography

Use fonts that support both Thai and Latin glyphs in the same family or a verified compatible pair.

Recommended hierarchy:
- H1: strong, compact, high contrast
- H2: section/page title
- H3: panel title / procedure label
- Body: generous line height and readable Thai size
- Caption: one step smaller than body, never tiny
- Table text: compact but readable at normal print scale

Do not rely on a Thai-only font for mixed English terms such as Workflow Agent, PDF, API, or product names unless Latin support is verified.

## Page Archetypes

### 1. Cover
Use one dominant title, one hero visual, short benefit strip, 3–4 feature boxes, and a stable footer. Avoid dense explanatory text.

### 2. Table of Contents / How to Use
Use grouped section cards with page references plus a compact process strip explaining how to use the manual.

### 3. Section Opener
Use chapter number, title, one-sentence purpose, key outcomes, and a restrained visual.

### 4. Procedure Page
Use a numbered step badge, realistic photo/virtual illustration, checklist panel, notes, warnings, and expected result. One page should answer one operational question.

### 5. Architecture / Workflow Page
Use a large primary diagram, a narrow component checklist, and 2–3 summary insight cards.

### 6. Comparison Page
Use side-by-side visuals with strong labels such as BEFORE/AFTER, PASS/FAIL, OLD/NEW, or OPTION A/B.

### 7. Checklist Page
Use short action rows with icons and explicit completion criteria.

### 8. Warning / Safety Page
Use high-contrast warning band, concise risk statement, prohibited action, and safe alternative.

### 9. Table / Reference Page
Use stable column widths, clear units, zebra or separator structure, and a note column for interpretation.

## Realistic / Virtual Illustration Policy

- Real photographs are preferred for exact physical locations, parts, equipment, and field procedures when available and accurate.
- Realistic virtual illustrations are appropriate when a real image is unavailable, a system concept needs explanation, or a clean controlled scene improves teaching.
- Simulated interfaces must be identified as illustrative if users could mistake them for exact product UI.
- Never invent labels, readings, part numbers, or safety values in a generated visual when those facts matter.

## Information Density

- Give each page one dominant communication goal.
- Prefer visual chunks over unbroken prose.
- Use 3–7 major elements per page as a practical target.
- Keep callouts concise.
- Split a crowded page rather than shrinking body text below a comfortable reading size.

## Consistency Rules

- One icon family per manual.
- One numbering style per manual.
- Reuse the same colors for the same semantics.
- Reuse page archetypes for repeated task types.
- Keep section labels, warning styles, and caption positions consistent.
